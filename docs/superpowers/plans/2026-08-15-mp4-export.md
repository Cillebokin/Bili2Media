# MP4 Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export a scanned Bilibili cache as MP4 by copying an existing complete MP4 or losslessly muxing one M4S video track with one M4S audio track.

**Architecture:** Keep cache locations, media references, probe results, export plans, and outcomes as pure data. Android adapters own File/SAF access, `MediaExtractor`, `MediaMuxer`, MediaStore, WorkManager, and notifications. A synchronous `Mp4ExportUseCase` orchestrates interfaces and is called by a thin foreground Worker; UI observes WorkManager and never touches media APIs.

**Tech Stack:** Kotlin, Android SDK 36, MediaExtractor, MediaMuxer, MediaStore, WorkManager 2.10.1, XML Views, LiveData/ViewModel, JUnit 4, AndroidJUnit4.

## Global Constraints

- Keep the existing single `app` Gradle module; enforce package boundaries that can later be extracted.
- Source cache files are read-only. Never rename, truncate, rewrite, delete, or repair source media.
- Support only complete MP4 copy and one-video-plus-one-audio M4S muxing.
- Do not support MP3, FLV, BLV, FFmpeg, transcoding, multi-segment concatenation, batch export, subtitles, danmaku, or embedding covers.
- Write outputs only through MediaStore to `Download/Bili2Media/Output` as `video/mp4`.
- Never overwrite an existing output. Use `Title.mp4`, then `Title (1).mp4`, `Title (2).mp4`, and so on.
- Ambiguous, missing, or unsupported tracks must produce a structured error; never guess across media groups.
- File and SAF adapters must stop at nested cache roots containing another `entry.json`.
- Long exports run as unique foreground WorkManager jobs, support progress and cancellation, and delete pending outputs on failure or cancellation.
- Do not run Git commands or create commits.
