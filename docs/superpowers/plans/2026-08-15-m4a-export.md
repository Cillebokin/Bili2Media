# M4A Export Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export the highest-quality AAC audio track from a scanned Bilibili cache as M4A without decoding or re-encoding it.

**Architecture:** Reuse cache discovery and media probing, then add an independent M4A planner, output store, native remux engine, use case, foreground Worker, and per-row UI state. Keep MP4 and M4A orchestration separate; share only truly format-neutral filename sanitization and request-order utilities.

**Tech Stack:** Kotlin, Android SDK 36, MediaExtractor, MediaMuxer, MediaStore Downloads, WorkManager 2.10.1, XML Views, LiveData/ViewModel, JUnit 4, AndroidJUnit4.

## Global Constraints

- Keep the existing single `app` Gradle module and enforce package boundaries.
- Do not run Git commands or create commits.
- Source cache files are read-only: never rename, truncate, rewrite, repair, or delete them.
- Support AAC MIME `audio/mp4a-latm` only.
- Support audio-only M4S, AAC extraction from MP4, and direct copying of valid M4A.
- Do not decode or re-encode AAC; do not add FFmpeg, NDK, LAME, MP3, WAV, or FLAC.
- Do not concatenate multiple audio segments or guess between multiple audio tracks in one file.
- Write outputs only through MediaStore to `Download/Bili2Media/Output` as `audio/mp4` with `.m4a` names.
- Never overwrite an existing output; use `Title.m4a`, `Title (1).m4a`, and so on.
- Long exports run as unique foreground WorkManager jobs, support progress and cancellation, and remove pending outputs on failure or cancellation.
- MP4 and M4A jobs and UI states remain independent.
